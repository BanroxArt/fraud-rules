# Compiled rules

Generated by `scripts/build_compiled.py` from the rule files. Do not edit; change the YAML and regenerate. `tests/test_compiled.py` fails if these are stale.

- `sql/duckdb/`: the SQL the compiler writes. Also runs unchanged on most Postgres versions.
- `sql/postgres/`, `sql/snowflake/`, `sql/bigquery/`: the same, rewritten by sqlglot. Postgres is executed in CI (on DuckDB); Snowflake and BigQuery are checked by parsing them back.
- `sigma/`: multi-document Sigma YAML for the rules that read only `events`.

Each SQL file selects `rule_id, anchor_table, anchor_id` from tables named `applications`, `transactions` and `events`. Point them at your views by search path, by renaming, or by generating with `python -m fraudrules sql --table events=myschema.v_events`.

Defaults are baked in. For other thresholds, regenerate with `--set RULE.param=value`.
